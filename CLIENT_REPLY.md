# Reply to Mrs. Lindner

Hi Sabine,

thanks for the email. We will build online returns in several iterations.
For the first stage, we want to focus on the core functionality to make the returns work. Here
is what we will have ready for you first:

- A customer finds their order with order number + email. No account, no password, exactly as you asked. A wrong combination reveals nothing.
- The page shows the ordered items and how many of each can still be returned.
- The customer selects items, a quantity and a reason per item, and submits the request.
- The returns will be validated by the server. The return window is 30 days. If someone ordered three mugs and wants to return two, that works, and the website will not let them return the same mug twice by mistake. Sale items and tea are refused automatically, with an explanation on the screen, unless the item arrived damaged: damaged items are always accepted within the 30 days, just as you said.
- You get a list of all return requests with the status open / approved / rejected, and can change the status.

**What is not in this first version**

A login for your list of return requests. In the first version the list has no password protection yet. This will be the top priority for the next iteration.

The automatic PayPal refund. Refunds still happen the way they do today. We want to first check if the returns
process itself is running reliably, and then we will include PayPal for automatic refunds.

Also not included for now: uploading a photo of a damaged item, an automatic
email to you when a return comes in, and the German version of the page. None of
them are forgotten; they are all straightforward to add once the core is live and
you have seen how your customers actually use it.

If you have any questions, I'd be happy to have a call with you.
